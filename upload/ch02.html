快速入门

你应该能够编写并运行像示例 2-1 这样的 Python 程序。

示例 2-1. 像这样运行的 Python 程序：this.py
def paid_promotion():
    print("(that calls this function!)")

print("This is the program")
paid_promotion()
print("that goes like this.")

为了展示如何在文本窗口或终端的命令行中执行该程序， 我将遵循惯例使用 $ 作为命令提示符（prompt） （也就是你的系统正眼巴巴地求着你赶紧输入点什么）。 你在提示符后面输入的内容均以粗体代码显示。 如果你将示例 2-1 保存为名为 this.py 的文件，就可以像示例 2-2 所示那样运行它。

示例 2-2. 测试 this.py
$ python this.py
This is the program
(that calls this function!)
that goes like this.

部分代码示例使用的是交互式 Python 解释器（interactive Python interpreter）， 只要直接在终端输入 python 回车即可进入该模式：

$ python
Python 3.9.1 (v3.9.1:1e5d33e9b9, Dec  7 2020, 12:10:52)
[Clang 6.0 (clang-600.0.57)] on darwin
Type "help", "copyright", "credits" or "license" for more information.
>>>

开头几行信息取决于你的操作系统与 Python 版本。 这里的 >>> 就是交互式提示符。 交互式解释器有一个很顺手的附加特性： 只要直接输入变量名，它就会自动把该变量的值打印出来：

>>> wrong_answer = 43
>>> wrong_answer
43

这一特性同样适用于表达式：

>>> wrong_answer = 43
>>> wrong_answer - 3
40

如果你刚接触 Python 不久， 或者想要快速复习一下基础知识， 请继续阅读接下来的几节内容。

Python 本身

作为最低要求，你需要安装 Python 3.7 或更高版本。 其中包含了类型提示（type hints）和 asyncio 等特性， 它们都是 FastAPI 的核心运行要求。 我建议至少使用 Python 3.9， 因为它拥有更长的官方支持生命周期。 获取 Python 的标准官方渠道是 Python 软件基金会（Python Software Foundation）网站。

包管理

在开发中，你会需要下载外部 Python 包并将它们安全地安装到计算机上。 完成这项工作的经典工具是 pip。

但你该如何下载这个“下载器”呢？ 如果你是从 Python 软件基金会官网安装的 Python， 那么系统中应该已经自带了 pip。 如果没有，请按照 pip 官网上的说明进行安装。 在本书各章中， 每当我引入一个新的 Python 包时， 都会附上对应的 pip 下载安装命令。

虽然单靠传统的 pip 就能完成许多工作，但你通常还会希望使用虚拟环境（virtual environments）， 并考虑像 Poetry 这样的替代工具。

虚拟环境

pip 会下载并安装软件包，但它应该把这些包放在哪里呢？ 虽然标准 Python 及其自带的标准库通常会安装在操作系统的标准目录中， 但你可能没有权限（而且通常也不应该）去修改那里的任何内容。 pip 默认会使用系统目录以外的另一个目录， 以免破坏系统自带的标准 Python 文件。 你也可以修改这一安装路径；具体操作请针对你的操作系统查阅 pip 官网文档。

不过在实际开发中，我们经常需要同时使用多个不同版本的 Python， 或者为特定项目创建独立的包安装环境，以便清楚地掌握项目里究竟安装了哪些包。 为此，Python 支持虚拟环境（virtual environments）。 它们本质上只是一些普通目录（在非 Unix 世界里常被称为文件夹［folder］）， pip 会把下载好的软件包写入其中。 当你激活（activate）某个虚拟环境时，你的 shell（主系统命令解释器）在加载 Python 模块时就会优先去该目录下查找。

用于管理虚拟环境的内置工具是 venv， 自 Python 3.4 版本起，它就已随标准 Python 一并内置提供。

让我们创建一个名为 venv1 的虚拟环境。 你可以将 venv 模块作为独立程序运行：

$ venv venv1

或者将其作为 Python 模块运行：

$ python -m venv venv1

要将其设为当前的 Python 环境， 请运行以下 shell 命令 （适用于 Linux 或 Mac；Windows 及其他系统请查阅 venv 文档）：

$ source venv1/bin/activate

现在，无论何时运行 pip install， 它都会将软件包安装到 venv1 目录下。 而且当你运行 Python 程序时， 系统也会从该目录下查找对应的 Python 解释器和模块。

要退出（deactivate）当前虚拟环境， 可以按下 Control-D（Linux 或 Mac），或者输入 deactivate（Windows，在 Linux/Mac 下同样适用）。

你可以创建像 venv2 这样的其他虚拟环境， 并通过退出/激活（deactivate/activate）在它们之间灵活切换 （不过希望你在起名字时比我更有想象力）。

Poetry

由于 pip 与 venv 的搭配使用实在太常见了，人们便开始将二者结合起来，以简化操作步骤， 并省去 source 那套繁琐的 shell 命令魔法。 这类工具之一是 Pipenv， 但一个名为 Poetry 的后起之秀正变得越来越受欢迎。

在先后使用过 pip、Pipenv 和 Poetry 之后， 我现在更青睐 Poetry。 你可以通过 pip install poetry 安装它。 Poetry 提供了许多子命令，例如使用 poetry add 向虚拟环境中添加软件包， 使用 poetry install 实际下载并安装依赖包， 等等。 你可以访问 Poetry 官网或直接运行 poetry 命令查看帮助信息。

除了下载单个软件包之外， pip 和 Poetry 还可以通过配置文件管理多个软件包： pip 使用 requirements.txt，而 Poetry 使用 pyproject.toml。 Poetry 和 pip 不仅负责下载软件包，还会管理包与包之间错综复杂的依赖关系。 你可以将所需的软件包版本指定为最低版本、最高版本、版本区间或精确版本号（这也被称为版本锁定［pinning］）。 随着项目规模不断扩大，以及所依赖的第三方包发生更新， 这项功能会变得尤为重要。 如果你用到的某个特性是在某个版本中首次引入的，你就需要指定最低版本； 而如果某个特性在后续版本中被移除了，你则需要限制最高版本。

源码格式化

源码格式化的重要程度虽不及前面几节介绍的工具，但依然非常有帮助。 借助能将源代码自动整理为标准、规范格式的工具， 你可以彻底避免团队在代码排版风格上陷入无休止的争论（即所谓的自行车棚效应［bikeshedding］）。 一个很好的选择是 Black。 你可以通过 pip install black 安装它。

测试

关于测试（testing）的详细内容将在第 12 章中深入探讨。 虽然 Python 标准库自带的测试包是 unittest， 但绝大多数 Python 开发者实际使用的工业级高强度测试框架是 pytest。 你可以通过 pip install pytest 安装它。

源码控制与持续集成

如今，源码控制领域几乎一统天下的解决方案是 Git， 并配合 GitHub 和 GitLab 等平台上的代码仓库（repositories，简称 repos）使用。 使用 Git 并非 Python 或 FastAPI 所独有， 但在日常开发中，你很可能会花大量时间与 Git 打交道。 pre-commit 工具可以在你将代码提交（commit）到 Git 之前， 先在本地机器上自动运行各项检查与测试（例如运行 black 和 pytest）。 而当代码推送（push）到远程 Git 仓库后， 远程仓库上还可以自动触发运行更多的持续集成（continuous integration，简称 CI）测试。

第 12 章以及第 13 章的“故障排查（Troubleshooting）”一节对此有更详细的介绍。

API 与服务

Python 的模块（modules）和包（packages）对于构建大型应用程序至关重要，能防止代码演变成一团乱麻的 “大泥球（big balls of mud）”。 即便是在单进程的 Web 服务中， 只要精心设计模块划分与导入关系，你依然能够保持第 1 章所讨论的层级分离架构。

Python 的内置数据结构极其灵活， 让人忍不住想在所有地方都直接使用它们。 但在接下来的章节中，你会看到我们可以定义更高层次的模型（models）， 从而让跨层级的通信变得更加清晰整洁。 这些模型依赖于 Python 近年新增的一项重要特性——类型提示（type hinting）。 我们马上就会深入介绍它， 但在那之前，先花一点篇幅聊聊 Python 是如何处理变量（variables）的。 别担心，这一点也不难理解。

变量即名称

在软件世界里，对象（object）一词有着许多种定义——甚至可能有点太多了。 在 Python 中，对象是一种封装了程序中每一个独立数据项的数据结构， 小到像 5 这样的整数，大到函数， 乃至你定义的任何内容，皆为对象。 除了其他内部管理信息之外，每个对象都明确记录了以下内容：

  • 一个唯一的标识值（identity）

  • 与底层硬件相对应的底层类型（type）

  • 具体的值（value，即物理比特位）

  • 记录当前有多少个变量正指向它的引用计数（reference count）

Python 在对象层面上是强类型的（strongly typed） （即对象的类型一旦创建便不会改变，尽管它的值可能会变）。 如果一个对象的值可以被修改，则称其为可变对象（mutable）； 如果不能被修改，则称其为不可变对象（immutable）。

然而在变量（variable）层面上， Python 与许多其他编程语言截然不同， 这一点有时容易让人感到困惑。在许多其他语言中， 变量本质上是一个直接指向某块内存区域的指针， 该内存区域中存放着原始的值， 并按照计算机硬件设计的位格式进行存储。 如果你给该变量赋一个新值， 语言会直接用新值覆盖内存中原来的旧值。

这种机制直接且高效。 编译器会全程追踪什么数据存放在什么位置。 这也是 C 等语言比 Python 运行得更快的原因之一。 作为开发者，你必须确保只向每个变量赋予正确类型的值。

现在，来看看 Python 最核心的区别所在： Python 的变量仅仅是一个名称（name）， 它只是临时与内存中的某个高层次对象（object）关联在一起。如果你向一个当前指向不可变对象的变量赋新值， 你实际上是在创建一个包含该新值的全新对象， 然后让这个变量名称转而指向那个新对象。 至于原来的旧对象（即该名称先前所指向的对象）则被解除了绑定， 如果没有任何其他名称仍然指向它（即其引用计数变为 0）， 它所占用的内存就可以被回收释放。

在《Python 语言及其应用》（Introducing Python，O’Reilly 出版）一书中， 我把对象比作摆放在内存货架上的塑料盒子， 而把名称/变量比作贴在这些盒子上的便利贴（sticky notes）。 或者，你也可以把名称想象成用细绳系在那些盒子上的标签牌。

通常情况下，当你使用一个变量名时， 你会将它绑定到某个对象上，并一直保持这种绑定关系。 这种简单的一致性有助于你理解自己的代码。 变量的作用域（scope）是指某个名称始终指向同一个对象的代码区域——例如在一个函数内部。 你可以在不同的作用域中使用相同的变量名， 但它们各自指向的是不同的对象。

尽管你可以在一段 Python 程序中让同一个变量名先后指向不同的对象， 但这通常并不是一个好习惯。 如果不仔细上下文查看，你根本无法一眼判断第 100 行的名称 x 与第 20 行的名称 x 是否处于同一个作用域中。 （顺便说一句，x 是个非常糟糕的变量名。 我们应当选用真正能够传达实际语义的名称。）

类型提示

前面铺垫的所有这些背景知识，都是为了引出这一节的核心主题。

Python 3.6 引入了类型提示（type hints）语法，用于声明某个变量所指向对象的类型。 请注意，Python 解释器在运行时并不会强制检查这些类型提示！ 相反，它们可供各种外部工具使用，以确保你在代码中使用变量的方式保持前后一致。 Python 标准的类型检查工具叫做 mypy， 稍后我会向你展示它的具体用法。

初看起来，类型提示似乎只是个锦上添花的小功能，就像程序员为了避免低级错误而使用的许多代码静态检查（lint）工具一样。 比如，它可以提醒你变量 count 指向的是一个 int 类型的 Python 对象。 但这些类型提示——尽管它们只是可选且不具强制性的注解（字面意义上的“提示”）—— 却展现出了意想不到的强大妙用。 在本书后面的章节中，你将看到 FastAPI 是如何结合 Pydantic 库， 对类型提示进行巧妙运用的。

为原本无类型声明的动态语言引入类型声明，或许正成为整个行业的一大趋势。 例如，许多 JavaScript 开发者如今都已经转向了 TypeScript。

Web 框架

除了其他功能之外，Web 框架的核心职责之一是在 HTTP 字节流与 Python 数据结构之间进行相互转换。 它能够为你省下大量繁琐的工作。 但另一方面，如果框架的某个部分无法按你需要的方式工作， 你就可能需要自己动手寻找变通方案（hack）了。 正如俗话所说：不要重复造轮子——除非你手头根本找不到一个圆的轮子。

Web 服务器网关接口（Web Server Gateway Interface，简称 WSGI）是一项同步的 Python 标准规范， 用于将应用程序代码与 Web 服务器连接起来。 传统的 Python Web 框架全部构建在 WSGI 之上。 然而，同步通信意味着在面对磁盘或网络等比 CPU 慢得多的操作时，往往会陷入忙等待（busy waiting）。 这时，你自然会寻求更好的并发（concurrency）能力。 近年来，并发的重要性日益凸显。 为此，Python 社区制定了 异步服务器网关接口（Asynchronous Server Gateway Interface，简称 ASGI）规范。 第 4 章将专门讨论这一主题。

Django

Django 是一个功能完备的全栈式 Web 框架， 它的官方标语是“为有截止日期的完美主义者打造的 Web 框架”。 它由 Adrian Holovaty 和 Simon Willison 于 2003 年发布， 并以 20 世纪比利时爵士吉他大师 Django Reinhardt 的名字命名。 Django 常被用于构建以数据库为支撑的企业级网站。 我将在第 7 章中详细介绍 Django 的更多细节。

Flask

相比之下， 由 Armin Ronacher 于 2010 年推出的 Flask， 则是一个微框架（microframework）。 第 7 章包含了关于 Flask 的更多信息， 并将它与 Django 和 FastAPI 进行了横向对比。

FastAPI

在舞会上见过了其他几位追求者之后， 我们终于迎来了令人眼前一亮的 FastAPI——也就是本书的主角。 尽管 FastAPI 由 Sebastián Ramírez 于 2018 年才正式发布， 但它已经跃居 Python Web 框架排行榜的第三位， 仅次于 Flask 和 Django， 而且增长势头比前两者更快。 2022 年的一项对比研究表明，它在未来某个时刻很可能会超越前两者。

注意

截至 2023 年 10 月底，这三大框架在 GitHub 上的 Star 数量如下：

  • Django：7.38 万（73.8 thousand）

  • Flask：6.48 万（64.8 thousand）

  • FastAPI：6.4 万（64 thousand）

在对各种替代方案进行了深入调研之后， Ramírez 提出了一套深度基于两个第三方 Python 包的架构设计：

  • 使用 Starlette 处理底层 Web 机制

  • 使用 Pydantic 处理数据定义与校验细节

在此基础上，他又加入了自己的独创设计与“秘制酱料”，打造出了最终的成品。 在下一章中，你将亲眼见证它的精妙之处。
