第 3 章 FastAPI 快速导览

FastAPI 是一个现代、快速（高性能）的 Web 框架，用于基于标准 Python 类型提示，使用 Python 3.6+ 构建 API。

Sebastián Ramírez，FastAPI 创始人

本章预览

FastAPI 由 Sebastián Ramírez 于 2018 年发布。 从许多方面来看，它都比大多数 Python Web 框架更加现代化——充分利用了过去几年间加入到 Python 3 中的新特性。 本章将对 FastAPI 的主要特性进行一次快速导览， 重点放在你最先需要掌握的核心技能上：如何处理 Web 请求（Requests）与响应（Responses）。

什么是 FastAPI？

与其他任何 Web 框架一样，FastAPI 旨在帮助你构建 Web 应用程序。 每一个框架的设计目标，都是通过其特性设计、功能取舍和默认配置，让某些特定操作变得更加轻松。 正如其名所示，FastAPI 专注于 Web API 的开发， 不过你同样可以用它来构建传统的 Web 内容应用程序。

FastAPI 官方网站列举了以下几大核心优势：

卓越的性能（Performance）

在某些场景下可与 Node.js 和 Go 比肩，这对于 Python 框架而言非同寻常。

更高的开发效率（Faster development）

没有暗坑（sharp edges）或古怪反直觉的设计。

更优的代码质量（Better code quality）

类型提示（type hinting）与数据模型有助于显著减少程序缺陷（Bug）。

自动生成的文档与测试页面（Autogenerated documentation and test pages）

比手写和维护 OpenAPI 描述文件要轻松太多了。

FastAPI 底层基于以下几项核心技术构建：

  • Python 类型提示（Type hints）

  • 使用 Starlette 提供底层 Web 机制，包括异步（async）支持

  • 使用 Pydantic 进行数据定义与数据校验

  • 专门的深度集成层，用于充分发挥并扩展上述组件的能力

这一套组合拳为 Web 应用程序——尤其是 RESTful Web 服务——营造出了令人愉悦的开发体验。

第一个 FastAPI 应用

让我们来编写一个袖珍的 FastAPI 应用程序——一个只包含单个端点的 Web 服务。 目前，我们仅处于前面所称的“Web 层（Web layer）”中， 只负责处理 Web 请求和响应。 首先，请安装我们将要使用的几个基础 Python 包：

  • FastAPI 框架：pip install fastapi

  • Uvicorn Web 服务器：pip install uvicorn

  • HTTPie 命令行文本 Web 客户端：pip install httpie

  • Requests 同步 Web 客户端库：pip install requests

  • HTTPX 同步/异步 Web 客户端库：pip install httpx

尽管 curl 是最广为人知的命令行文本 Web 客户端， 但我认为 HTTPie 用起来更加顺手。 此外，HTTPie 默认采用 JSON 编码与解码， 这与 FastAPI 的默认行为更加契合。 在本章稍后部分， 你会看到一张截图，其中也展示了访问特定端点所需的 curl 命令行语法。

现在，让我们在示例 3-1 中模仿一位性格内向的 Web 开发者， 并将这段代码保存为文件 hello.py。

示例 3-1. 一个害羞的端点（hello.py）
from fastapi import FastAPI

app = FastAPI()

@app.get("/hi")
def greet():
    return "Hello? World?"

这里有几个值得注意的关键点：

  • app 是代表整个 Web 应用程序的顶层 FastAPI 对象。

  • @app.get("/hi") 是一个路径装饰器（path decorator）。 它向 FastAPI 声明了以下信息：

    • 发往本服务器上 URL "/hi" 的请求，应当交由紧随其后的函数来处理。

    • 该装饰器仅针对 HTTP GET 动词生效。 你也可以编写其他独立的函数，来响应使用其他 HTTP 动词（如 PUT、POST 等）发往同一个 "/hi" URL 的请求。

  • def greet() 是一个路径函数（path function）——它是与 HTTP 请求和响应打交道的主要接触点。 在本例中它没有任何参数， 但接下来的几节会向你展示，FastAPI 的引擎盖下还藏着丰富得多的功能。

下一步是在 Web 服务器中运行这个 Web 应用程序。 FastAPI 本身并不内置 Web 服务器， 但官方推荐使用 Uvicorn。 你可以通过两种方式启动 Uvicorn 和 FastAPI Web 应用：外部启动或内部启动。

若要通过命令行从外部启动 Uvicorn，请参见示例 3-2。

示例 3-2. 使用命令行启动 Uvicorn
$ uvicorn hello:app --reload

其中的 hello 指的是 hello.py 文件， 而 app 则是该文件中定义的 FastAPI 变量名。

或者，你也可以在应用程序代码内部直接启动 Uvicorn，如示例 3-3 所示。

示例 3-3. 在代码内部启动 Uvicorn
from fastapi import FastAPI

app = FastAPI()

@app.get("/hi")
def greet():
    return "Hello? World?"

if __name__ == "__main__":
    import uvicorn
    uvicorn.run("hello:app", reload=True)

无论采用哪种方式， 其中的 reload 参数都会告诉 Uvicorn：一旦 hello.py 文件发生更改，就自动重启 Web 服务器。 在本章中，我们将频繁使用这项自动热重载功能。

这两种启动方式默认都会使用本机（主机名为 localhost）的 8000 端口。 如果你希望使用其他主机地址或端口号，外部命令和内部调用方法都支持传入 host 和 port 参数进行自定义。

现在，服务器已经拥有了一个端点（/hi），并准备好接收请求了。

让我们使用多种不同的 Web 客户端对它进行测试：

  • 对于浏览器：直接在顶部的地址栏中输入 URL。

  • 对于 HTTPie：在终端中输入所示的命令（其中 $ 代表你系统 shell 的命令提示符）。

  • 对于 Requests 或 HTTPX：进入 Python 交互模式，并在 >>> 提示符后输入代码。

HTTP 请求

示例 3-9 中只包含了一个非常具体的请求： 向服务器 localhost 的 8000 端口上的 /hi URL 发起一个 GET 请求。

Web 请求往往会把数据像松鼠藏坚果一样藏在 HTTP 请求报文的各个不同位置， 而 FastAPI 能让你行云流水般地提取出这些数据。 摘自示例 3-9 中的示例请求， 示例 3-10 展示了 http 命令实际发送给 Web 服务器的 HTTP 请求报文。

示例 3-10. 一个 HTTP 请求报文
GET /hi HTTP/1.1
Accept: /
Accept-Encoding: gzip, deflate
Connection: keep-alive
Host: localhost:8000
User-Agent: HTTPie/3.2.1

该请求包含以下内容：

  • HTTP 动词（GET）与路径（/hi）

  • 任意查询参数（query parameters）（即 ? 后面的文本，本例中没有）

  • 其他 HTTP 请求头（Headers）

  • 无请求体（request body）内容

FastAPI 将这些藏在各处的数据提取并封装成了几个非常顺手的定义对象：

Header

HTTP 请求头

Path

URL 路径

Query

查询参数（位于 URL 末尾的 ? 之后）

Body

HTTP 请求体

注意

FastAPI 从 HTTP 请求的不同部分提取并提供数据的方式， 是它最出色的特性之一，也是相比大多数传统 Python Web 框架的重大改进。 你所需要的所有参数，都可以直接使用上述列表中的定义（Path、Query 等）或者你自己编写的函数， 直接在路径函数的参数列表中声明并获取。 这背后使用了一项名为依赖注入（dependency injection）的技术， 我们会在后续内容中逐步接触，并在第 6 章中进行深入展开。

让我们为前面的应用程序增添一点人情味： 添加一个名为 who 的参数，使那句略显羞怯的 Hello? 能够向特定的人打招呼。我们将尝试通过以下几种不同方式来传递这个新参数：

  • 在 URL 路径（path）中传递

  • 作为查询参数（query parameter），放在 URL 的 ? 之后传递

  • 在 HTTP 请求体（body）中传递

  • 作为 HTTP 请求头（header）传递

URL 路径

请按示例 3-11 修改 hello.py。

示例 3-11. 从路径中获取参数并返回问候语
from fastapi import FastAPI

app = FastAPI()

@app.get("/hi/{who}")
def greet(who):
    return f"Hello? {who}?"

当你在编辑器中保存这一修改后， Uvicorn 应该会自动重启。 （否则的话，我们就得每次新建 hello2.py 等文件并手动重新运行 Uvicorn 了。） 如果你不小心打错了字导致报错，只需继续修改并保存，直到修复错误为止， Uvicorn 不会因此给你找麻烦。

在 URL 中（@app.get 后面）添加 {who}， 是在告诉 FastAPI：预期在 URL 的该位置上会出现一个名为 who 的变量。 随后，FastAPI 会自动将该值赋给下方 greet() 函数中的 who 参数。 这体现了路径装饰器与路径函数之间的默契协同。

注意

请不要在这里把修改后的 URL 字符串（"/hi/{who}"）写成 Python 的 f-string（即不要加前缀 f）。 这里的花括号是由 FastAPI 自身负责解析的，用于将 URL 片段匹配为路径参数。

每种方式收到的响应都是 JSON 字符串 （具体显示为单引号还是双引号，取决于你使用的是哪种测试客户端） "Hello? Mom?"。

查询参数

查询参数（Query parameters）是 URL 中位于 ? 之后的 name=value（键值对）字符串， 多个参数之间用 & 字符分隔。 请按示例 3-15 再次修改 hello.py。

示例 3-15. 从查询参数中获取参数并返回问候语
from fastapi import FastAPI

app = FastAPI()

@app.get("/hi")
def greet(who):
    return f"Hello? {who}?"

这里的端点函数依然定义为 greet(who)， 但这一次，上方装饰器行的 URL 中不再包含 {who} 了， 因此 FastAPI 现在会自动推断 who 是一个查询参数。 请使用示例 3-16 和 3-17 进行测试。

示例 3-16. 使用浏览器测试示例 3-15
localhost:8000/hi?who=Mom
示例 3-17. 使用 HTTPie 测试示例 3-15
$ http -b localhost:8000/hi?who=Mom
"Hello? Mom?"

在示例 3-18 中， 你也可以使用专门的查询参数语法来调用 HTTPie （请注意使用的是双等号 ==）。

示例 3-18. 使用 HTTPie 及独立参数语法测试示例 3-15
$ http -b localhost:8000/hi who==Mom
"Hello? Mom?"

在 HTTPie 中你可以传入多个这样的参数， 而且将它们写成以空格分隔的参数形式，在命令行中输入起来要方便得多。

示例 3-19 和 3-20 展示了在 Requests 库中对应的两种等价写法。

示例 3-19. 使用 Requests 测试示例 3-15
>>> import requests
>>> r = requests.get("http://localhost:8000/hi?who=Mom")
>>> r.json()
'Hello? Mom?'
示例 3-20. 使用 Requests 及 params 参数测试示例 3-15
>>> import requests
>>> params = {"who": "Mom"}
>>> r = requests.get("http://localhost:8000/hi", params=params)
>>> r.json()

在以上每一个示例中，你都通过一种新的方式提供了 "Mom" 字符串， 并将它一路传递给路径函数，最终包含在响应结果中返回。

请求体（Body）

我们可以向 GET 端点传递路径参数或查询参数， 但不能通过请求体（request body）向其传递数据。 在 HTTP 规范中，GET 请求应当是 幂等的（idempotent）——这是一个计算机术语，意思是“问同一个问题，总是得到同一个答案”。 HTTP GET 只应当用于获取并返回数据。 而请求体则是用来在创建资源（POST）或更新资源（PUT 或 PATCH）时，向服务器发送数据的。 第 9 章会介绍绕开这一限制的特殊方法。

因此，在示例 3-21 中， 让我们把端点从 GET 改为 POST。 （严格从技术规范上讲，我们并没有真正创建任何资源， 所以这里用 POST 并不算完全正统； 但就算“RESTful 最高法庭”真因为这事起诉我们， 嘿，去参观一下酷炫的法院也不赖嘛。）

示例 3-21. 从请求体中获取参数并返回问候语
from fastapi import FastAPI, Body

app = FastAPI()

@app.post("/hi")
def greet(who:str = Body(embed=True)):
    return f"Hello? {who}?"
注意

这里的 Body(embed=True) 是必需的， 它用来告诉 FastAPI：这一次，我们要从 JSON 格式的请求体中获取 who 的值。 其中的 embed=True 表示请求体应当是一个形如 {"who": "Mom"} 的键值对对象， 而不是光秃秃的一个字符串 "Mom"。

组合多种请求数据

你可以在同一个路径函数中同时使用上述多种参数获取方式。 也就是说，你可以同时从 URL 路径、查询参数、HTTP 请求体、HTTP 请求头、Cookie 等位置提取数据。 此外，你还可以编写自己的依赖项函数（dependency functions）， 以特定的方式对这些参数进行处理与组合， 例如用于实现分页（pagination）或身份认证（authentication）。 你将在第 6 章以及第 III 部分的多个章节中看到这些用法的具体示例。

哪种方式最合适？

以下提供几条实用的经验建议：

  • 在 URL 路径中传递参数时，遵循 RESTful 设计规范是业界的标准做法。

  • 查询字符串（Query strings）通常用于提供可选参数，例如分页参数。

  • 请求体（Body）通常用于传输体量较大的输入数据，例如完整或部分数据模型。

在以上所有情况中， 只要你在数据定义中提供了类型提示（type hints）， Pydantic 就会自动对传入的参数执行类型检查。 这确保了参数不仅存在，而且类型与格式完全正确。

HTTP 响应

默认情况下， FastAPI 会把你从端点函数中返回的任何内容自动转换为 JSON；并且 HTTP 响应中会带有一行响应头： Content-type: application/json。 因此，尽管最初的 greet() 函数返回的是 Python 字符串 "Hello? World?"， FastAPI 依然会将它转换为 JSON 格式。 这是 FastAPI 为了简化 API 开发而精心选择的默认行为之一。

在这个例子里， Python 字符串 "Hello? World?" 被转换成了等价的 JSON 字符串 "Hello? World?"， 两者看起来完全一模一样。 但实际上，无论你返回的是什么——不管是 Python 内置类型还是 Pydantic 模型——都会被自动转换为 JSON。

状态码

默认情况下，FastAPI 返回 200 状态码； 而出现异常时则会抛出 4xx 状态码。

你可以在路径装饰器中指定当一切正常执行时应当返回的 HTTP 状态码 （如果发生异常，异常处理器会生成各自对应的状态码并将其覆盖）。 请将示例 3-28 中的代码添加到你的 hello.py 文件中 （为了避免一遍又一遍地重复展示整个文件，这里只列出新增代码）， 然后使用示例 3-29 对其进行测试。

示例 3-28. 指定 HTTP 状态码（添加到 hello.py）
@app.get("/happy")
def happy(status_code=200):
    return ":)"
示例 3-29. 测试 HTTP 状态码
$ http localhost:8000/happy
HTTP/1.1 200 OK

响应头（Headers）

你可以向响应中注入自定义的 HTTP 响应头， 如示例 3-30 所示（你不需要手动返回 response 对象）。

示例 3-30. 设置 HTTP 响应头（添加到 hello.py）
from fastapi import Response

@app.get("/header/{name}/{value}")
def header(name: str, value: str, response:Response):
    response.headers[name] = value
    return "normal body"

让我们测试一下它是否生效（见示例 3-31）。

示例 3-31. 测试自定义的 HTTP 响应头

响应类型

常见的响应类型（可从 fastapi.responses 导入这些类）包括以下几种：

  • JSONResponse（默认响应类型，JSON 响应）

  • HTMLResponse（HTML 响应）

  • PlainTextResponse（纯文本响应）

  • RedirectResponse（重定向响应）

  • FileResponse（文件响应）

  • StreamingResponse（流式响应）

我将在第 15 章中详细介绍最后两种响应类型。

对于其他输出格式 （也称为 MIME 类型［MIME types］），你可以使用通用的 Response 类，它需要接收以下参数：

content

字符串（str）或字节串（bytes）

media_type

表示 MIME 类型的字符串

status_code

整型的 HTTP 状态码

headers

由字符串组成的字典（dict）

类型转换

路径函数可以返回任何内容，默认情况下（使用 JSONResponse）， FastAPI 会将其转换为 JSON 字符串并返回， 同时附带匹配的 HTTP 响应头 Content-Length 和 Content-Type。 这其中也包括任何 Pydantic 模型类。

但它是如何做到这一点的呢？ 如果你用过 Python 标准库的 json 模块， 你很可能遇到过当传入某些特殊数据类型（例如 datetime）时，它会直接抛出异常。 FastAPI 内部使用了一个名为 jsonable_encoder() 的函数， 先将任意数据结构安全地转换为“可 JSON 序列化（JSONable）”的 Python 基础数据结构， 然后再调用常规的 json.dumps() 将其转换为 JSON 字符串。 示例 3-32 展示了一个可以使用 pytest 运行的测试用例。

示例 3-32. 使用 jsonable_encoder() 避免 JSON 序列化崩溃
import datetime
import pytest
from fastapi.encoders import jsonable_encoder
import json

@pytest.fixture
def data():
    return datetime.datetime.now()

def test_json_dump(data):
    with pytest.raises(Exception):
        _ = json.dumps(data)

def test_encoder(data):
    out = jsonable_encoder(data)
    assert out
    json_out = json.dumps(out)
    assert json_out

模型类型与 response_model

在实际开发中，我们经常会定义几个拥有许多相同字段的不同类， 其中一个专门用于接收用户输入，一个专门用于返回输出，还有一个供内部处理使用。需要定义这些模型变体的常见原因包括：

  • 从输出结果中剔除某些敏感信息——比如对个人医疗数据进行去标识化（脱敏，deidentifying），如果你接触过美国《健康保险流通与责任法案》（HIPAA）合规要求的话一定对此不陌生。

  • 在用户输入数据的基础上补充额外字段（例如添加创建日期与时间戳）。

示例 3-33 针对一个简化的假设场景展示了三个相互关联的类：

  • TagIn 类定义了用户需要提供的输入数据（在本例中只是一个名为 tag 的字符串）。

  • Tag 类由 TagIn 构造而来，并额外增加了两个字段： created（记录该 Tag 创建的时间）和 secret（一个内部机密字符串，可能存储在数据库中，但绝不应该对外暴露给外界）。

  • TagOut 类定义了可以返回给用户的数据结构（例如通过查询或搜索端点返回）。它包含了来自原始 TagIn 对象及其派生的 Tag 对象的 tag 字段，外加为 Tag 生成的 created 字段，但不包含 secret 字段。

示例 3-33. 数据模型的不同变体（model/tag.py）
from datetime import datetime
from pydantic import BaseClass

class TagIn(BaseClass):
    tag: str

class Tag(BaseClass):
    tag: str
    created: datetime
    secret: str

class TagOut(BaseClass):
    tag: str
    created: datetime

你有多种方式可以让 FastAPI 路径函数返回特定结构的数据类型。 其中一种方法是在路径装饰器中使用 response_model 参数，指示 FastAPI 将返回值转换为指定的目标模型。 FastAPI 会自动丢弃掉你返回的对象中存在、但未在 response_model 指定模型中声明的所有多余字段。

在示例 3-34 中，假设你已经编写了一个名为 service/tag.py 的新服务层模块， 其中包含 create() 和 get() 函数供这个 Web 层模块调用。 那些下层实现细节在这里并不重要。 真正需要注意的是底部的 get_one() 路径函数， 以及其路径装饰器中的 response_model=TagOut。 它会自动将一个内部的 Tag 对象转换为經過脱敏处理的 TagOut 对象。

示例 3-34. 使用 response_model 返回不同的响应模型类型（web/tag.py）
import datetime
from model.tag import TagIn, Tag, TagOut
import service.tag as service

@app.post('/')
def create(tag_in: TagIn) -> TagIn:
    tag: Tag = Tag(tag=tag_in.tag, created=datetime.utcnow(),
        secret="shhhh")
    service.create(tag)
    return tag_in

@app.get('/{tag_str}', response_model=TagOut)
def get_one(tag_str: str) -> TagOut:
    tag: Tag = service.get(tag_str)
    return tag

尽管我们在函数代码中返回的是一个 Tag 对象， 但 response_model 会自动将其过滤并转换为一个 TagOut 对象。

复杂数据

以上示例仅展示了如何向端点传递单个字符串。 许多端点（尤其是 GET 或 DELETE 端点）可能根本不需要任何参数， 或者只需要少数几个像字符串、数字这样的简单参数。 但是在创建（POST）或修改（PUT 或 PATCH）资源时， 我们通常需要传递更加复杂的数据结构。 第 5 章将展示 FastAPI 如何借助 Pydantic 和数据模型（data models）， 优雅、整洁地实现复杂数据处理。

本章回顾

在本章中，我们使用 FastAPI 创建了一个包含单个端点的 Web 站点， 并使用多种 Web 客户端对它进行了测试：Web 浏览器、HTTPie 命令行文本工具、Requests Python 库以及 HTTPX Python 库。 我们从一个简单的 GET 调用开始， 先后通过 URL 路径、查询参数和 HTTP 请求头将请求参数传递给服务器； 接着，又使用 HTTP 请求体向 POST 端点发送了数据。 随后，本章展示了如何返回各种不同类型的 HTTP 响应。 最后，自动生成的交互式表单页面同时提供了 API 文档与在线测试表单，成为了我们的第四种测试客户端。
